# Design notes

## Goal

A production-shaped (but small) RAG service that answers Vietnamese customer
questions over a shop's internal knowledge base, with source citations,
conversation memory and an evaluation harness — the same shape as a real
"AI support agent" deployment.

## Architecture

```
        ┌────────────┐   ingest   ┌──────────────┐
        │ .txt/.md/  │ ─────────▶ │   loaders    │ ─┐
        │ .pdf docs  │            └──────────────┘  │
        └────────────┘                              ▼
                                        ┌────────────────────┐
                                        │ recursive splitter │  ~800 chars, 120 overlap
                                        └────────────────────┘
                                                  │ embed
                                                  ▼
                                        ┌────────────────────┐
                                        │      ChromaDB      │  cosine index, persisted
                                        └────────────────────┘
                                                  ▲
 question ──▶ embed ──▶ top-k retrieve ──▶ prompt │─▶ LLM (Groq, OpenAI-compatible)
                                                  │         │
                                                  └── answer + [1][2] citations ◀─┘
```

## Key decisions

| Decision | Rationale |
|---|---|
| FastAPI + Pydantic v2 | Standard for model-serving APIs; free OpenAPI docs at `/docs` |
| ChromaDB (embedded) | Zero-infra persistent vector store; hidden behind `VectorStore` protocol so Qdrant/pgvector is a drop-in swap |
| `vietnamese-bi-encoder` (BKAI) | Bi-encoder trained specifically for Vietnamese semantic similarity; configurable via `EMBEDDING_MODEL` |
| Hand-rolled recursive chunker | Paragraph → line → sentence → word fallback with an overlap carry window; no framework magic, easy to explain/tune |
| Groq via OpenAI-compatible client | Free tier, low latency; changing provider = changing `LLM_BASE_URL` |
| `MockLLM` + `HashEmbedder` fallbacks | Whole app + test suite runs with no API key and no 400MB model download; CI stays fast and deterministic |
| Deterministic chunk IDs (sha256) | Re-ingesting is an upsert — no duplicate chunks |
| In-memory `SessionStore` | Dict-of-deques with TTL; documented swap path to Redis for multi-worker deployments |

## Deliberately out of scope

- Auth/RBAC, rate limiting — internal-tool scope
- Fine-tuning — RAG already grounds answers; training adds cost with no demo benefit
- Frontend — API-first; any web UI can consume `/chat` + `/chat/stream`

## Score threshold calibration

`vietnamese-bi-encoder` produces modest cosine similarities on this corpus —
relevant chunks score ~0.15–0.4, off-topic queries top out ~0.11 — so the
default `SCORE_THRESHOLD` is **0.15**, not the 0.25+ typical of English models.
Measured on the bundled testset: switching embedding model means re-tuning this
value (`scripts/evaluate.py` is the tool for that).

## Known trade-offs

- `MockLLM` answers are extractive (echoes top chunk) — exists so the repo runs
  offline. With `GROQ_API_KEY` set, answers are generated by the real model.
- `HashEmbedder` retrieval is keyword-overlap only — fine for tests, not for demos.
- Single-process session memory — multi-instance deployments need Redis.
